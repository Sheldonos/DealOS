# DoorDash Constraint Removal Framework

This skill provides a strategic methodology for identifying billion-dollar software opportunities by applying the "DoorDash insight."

## The Core Insight

DoorDash did not invent food delivery. It simply asked: *"Why does delivery only work for Chinese food and pizza?"* The answer was an artificial constraint — not a structural one. Removing it created an $80B company. The same logic applies to dozens of software categories today.

## The Framework Anatomy

Every DoorDash-style opportunity shares the same four components:

1. **The Existing Narrow Solution**: Software that already works well, but only for one sub-type of a broader category.

1. **The Artificial Constraint**: The assumption — usually historical, cultural, or lazy — that limits the solution to that sub-type.

1. **The Unlocked Horizontal**: What the product becomes when the constraint is removed and the solution is applied universally.

1. **The Overlooked Reason**: Why no one has done it yet (incumbents too comfortable, market too fragmented, founders too close to the original vertical).

*Key distinction*: A structural constraint means the solution genuinely cannot work elsewhere. An artificial constraint means it just hasn't been tried.

## Execution Workflow

When a user asks you to find new software opportunities, brainstorm startup ideas, or analyze market white space using this framework, follow these steps:

### Step 1: Identify the Seed (The Narrow Solution)

Look for a highly successful, mature software company that serves a very specific niche.*Examples: TurboTax (taxes), Guesty (Airbnb), ServiceTitan (HVAC), Zola (weddings).*

### Step 2: Isolate the Core Mechanism

What is the actual, underlying problem the software solves, stripped of its industry context?*Example: TurboTax doesn't solve "taxes." It solves "guided self-service for government-mandated compliance."*

### Step 3: Identify the Artificial Constraint

Why is this software only used in this one vertical? Is it a hard technical limitation, or just historical momentum?*Example: Guesty is for Airbnb because Airbnb had the scale to justify vertical software first. But the operational problem (calendar sync, deposits, messaging) applies to renting ANY asset.*

### Step 4: Map the Horizontal Expansion

What other industries have the exact same core mechanism/problem, but lack the software?*Example: If ServiceTitan works for HVAC, it should work for mobile vets, mobile notaries, and pool cleaners.*

### Step 5: Validate the Overlooked Reason & TAM

Explain why the gap exists and estimate the Total Addressable Market (TAM) of the unlocked horizontal.

## Required Deliverable Format

When presenting opportunities using this framework, structure your output using this table format for clarity:

| Component | Analysis |
| --- | --- |
| **The Existing Narrow Solution** | [Name the existing successful software and its niche] |
| **The Artificial Constraint** | [State the assumption limiting it to that niche] |
| **The Unlocked Horizontal** | [List the new markets/industries this unlocks] |
| **The Overlooked Reason** | [Explain why it hasn't been built yet] |
| **Estimated TAM** | [Provide a data-backed estimate of the new market size] |
